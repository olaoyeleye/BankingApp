BankingApp — Architecture & Environment Guide

1. Workflow Execution Order

1. Provision Infra
infra.yml (manual)
then
2. Deploy App
apply.yml (push)
or
3. Destroy
destroy.yml (manual)

Step 1: Run infra.yml manually to create the EKS cluster (Terraform + Ansible).
Step 2: Push to dev/test/prod to deploy the application via Helm.
Step 3: Run destroy.yml manually to tear down an environment or infrastructure.

3. Workflows

1. Provision Infrastructure (infra.yml)

  • Trigger: Manual only
  • Terraform init, plan, apply — creates VPC, EKS, EC2, ECR, IAM
  • Configures Ansible inventory with EC2 public IP
  • Runs Ansible: installs kubectl, Helm, ingress-nginx, Datadog operator
  • Must run before deploying applications

2. Deploy Application (apply.yml)

  • Trigger: Push to dev/test/prod, or manual dispatch
  • Detects environment from branch name
  • Builds 5 Docker images, pushes to ECR
  • Deploys via helm upgrade --install with environment-specific values
  • Production requires GitHub Environment approval

3. Destroy (destroy.yml)

  • Trigger: Manual only
  • Uninstalls Helm release + deletes namespace for selected environment
  • Optional destroy_infra flag also runs terraform destroy (requires prod approval)

4. Helm Chart

Chart at helm/banking-app/ with 12 templates. Values are layered:

helm upgrade --install banking-app ./helm/banking-app \
  -f values.yaml -f values-{env}.yaml \
  --set ecrRegistry=... --set imageTag=...

5. Production Approval Setup

  1. GitHub Settings → Environments → New environment
  2. Create dev, test, prod
  3. For prod: enable Required reviewers, add your team
  4. Pushes to prod branch will pause until approved
